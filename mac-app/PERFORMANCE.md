# 常驻性能核查（2026-10-10，0.3.1）

目标：减少后台 CPU 和唤醒，保持 Google / 小米的语音与各自按键设置，核查对其他音频设备的影响。

## 实测结果

同一台 Mac、Google 已连接、设置窗口关闭。每秒读取进程累计资源用量；剔除语音和会话边界区间。CPU 为单个核心百分比。

| 指标 | 0.3.0 | 最终 0.3.1 |
| --- | ---: | ---: |
| 有效空闲样本 | 39.16 秒 | 41.16 秒 |
| 平均空闲 CPU | 0.203% | 0.126% |
| 进程中断唤醒 | 1.86 次/秒 | 0.92 次/秒 |
| package idle 唤醒 | 0.41 次/秒 | 0.10 次/秒 |
| 空闲逻辑写入 | 0 字节 | 0 字节 |
| 样本结束物理内存占用 | 47.94 MiB | 41.91 MiB |

本次样本的空闲 CPU 降低约 38%，中断唤醒降低约 50%。原版 CPU 本身已不高，优化主要减少常驻时的无用工作。内存差值可能受重启和缓存影响，不把它认定为本次代码优化的收益。

短时结果会波动：中间构建另一段 32 秒空闲样本为 0.037%，最终结果采用上表的最终构建，不选择最低值宣传。最终样本中的约 19 秒语音平均 CPU 为 1.51%，录音内容与时长不同，不作为优化前后语音性能对比。

这些是 App 进程数据，不代表整机功耗、续航或微信/CoreAudio 的总成本。没有声称省电百分比。

另用 `ps` 观察既有音频驱动宿主进程：22.27 秒有效空闲区间内累计 CPU 时间没有可测增长；`ps` 精度为 0.01 秒，不能解释为绝对零消耗。驱动属于系统音频用户，详细资源计数没有读取权限，本次没有为测量提权或改动系统权限。

## 具体改动

- 设置窗口关闭、最小化或 App 隐藏后停止页面状态刷新；空闲维护从每 1 秒改为每 10 秒。可见设置、语音会话、连招录入/验证期间保持 1 秒检查。
- 原有 HID 和蓝牙按键/音频回调仍即时处理；新增 HID 连接事件、系统唤醒和会话通知来及时更新状态，输入不等待 10 秒定时器。
- 输入监控权限结果在 1 秒内复用，减少同一轮刷新重复 `IOHIDCheckAccess` 的同步系统调用。真实注入仍在执行时检查辅助功能权限。
- 新设备扫描只由手动按钮触发，最多 20 秒；连接、手动停止、蓝牙关闭、切换型号和退出时停止扫描。没有后台反复发现设备的定时器。
- 每种型号只记住已完成语音协商的设备 ID，断开后定向重连。系统等待休眠设备期间无 App 连接轮询；明确失败最多按 2/10/30 秒重试三次。已建立连接的语音初始化仍有 15 秒超时。
- 音频解码、Fn 时序、虚拟声卡、按键定义和两套保存结构保持原实现。长按切换系统输入、会话结束恢复原麦克风的行为保留。

连接成功本来就停止扫描；扫描修改解决的是原先断开后自动扫描的行为。因此不能把已连接状态的 CPU 降幅归因于扫描修改。

## 验证范围

- Swift warnings-as-errors 类型检查、优化构建、签名验证、差异格式检查通过。
- 临时蓝牙模拟检查覆盖两种型号：启动不扫描、手动扫描/停止/20 秒截止、型号过滤、真实能力报文协商、分型号记住设备、定向重连、失败次数上限、取消、蓝牙关闭和退出。模拟检查不代替所有硬件断连场景实测。
- 最终 App 本机启动成功，Google 已连接，主动扫描计数为 0；已完成真实语音会话。连接时界面按钮为禁用的“已连接”。关闭设置后维护间隔为 10 秒。
- Google 与小米的个人映射数据和所选型号均与修改前备份一致。用户已确认前一性能构建语音“正常，没有明显变化”；最终构建语音完成计数正常，未把计数当作文字准确率测试。
- 小米语音此前已由用户实机验证；本轮没有重新要求用户重复全部实体按键测试。
- 正常语音的默认输入恢复、输出不切换与虚拟声卡空闲状态已观察，详见 [音频设备影响核查](AUDIO-BEHAVIOR.md)。

## 测量方法与原始记录

使用 macOS `proc_pid_rusage` 的累计 user/system time、interrupt/package wakeups、logical writes 和 physical footprint。CPU = 两次累计 CPU 时间差 / 墙钟时间差 × 100；此机计时字段按 Mach timebase 125/3 换算，已用 `ps` 累计 CPU 时间校核。物理内存占用使用 footprint，不把 RSS 当作同一指标。

本机原始文件保留在忽略目录 `build/performance/`：`before-background.json`、`final-background.json`、中间样本、栈采样与测量脚本。最终整段采样 60.24 秒；按相邻状态中 sessionActive/Fn 计数剔除约 19.08 秒语音区间。设置打开的样本另存为 `final-settings-visible.json`，未混入上表。

更长时间的电量测量、其他 Mac 型号、所有蓝牙耳机和会议软件组合，尚未验证。现阶段无需为常驻性能改写语音解码或增加后台服务。
