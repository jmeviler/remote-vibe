# Google 普通键语音验证

开发基线：`5d8d342`（0.4.0），新版本 0.4.1 / build 9。

## 已完成的硬件验证

2026-10-11，在用户自己的 Google Chromecast Remote 上，用独立 Swift / CoreBluetooth 程序验证软件直接开麦。用户确认整轮没有按原语音键。

- 能力：ATVV 1.0、16 kHz、160 字节音频包，能力应答 `0b0100020300a00000`。
- 从空闲状态发送 `MIC_OPEN 0c00`，收到 `AUDIO_START 04000200`（reason 0、stream 0）。
- 8 秒测试窗口收到 390 个音频包、124800 个样本，约 7.8 秒；峰值 12240，RMS 485.5。
- 发送 `MIC_CLOSE 0d00` 后，收到 2 个在途包及 `AUDIO_STOP 0000`，之后没有继续传输音频。
- 测试没有使用虚拟声卡、没有保存录音，没有改变正式 App 源码；结束后恢复原 App。

这证明该样机可以由电脑直接开麦，不代表每种 Google 固件都支持，也不代表小米支持此功能。普通键动作接入完成后的文字识别、按键手感仍需人工验收。

## 自动检查

从项目根目录运行：

```sh
zsh mac-app/Tests/test-remote-voice.sh
zsh mac-app/Tests/test-button-gestures.sh
zsh mac-app/build.sh
```

- 语音会话测试：普通键开麦、提前松开、迟到应答、重复请求拒绝、开麦无响应、零音频超时、精确 stream id 关麦、在途尾音、关麦无应答的限时退出、取消、55 秒上限及取消后的定时器清理。
- 兼容测试：Google 原语音键 / START_SEARCH、ATVV 0.4 / 1.0、前置 AUDIO_SYNC、小米原语音键、RC003 完整帧累积、不向小米发送普通键开麦。
- 手势和设置页：普通键即时保持与长按阈值、旧配置兼容、语音动作保存格式、单击/长按冲突、双击禁用、Google 显示 / 小米隐藏、固定原语音键与 Fn 语义保留。

以上检查不连接蓝牙、不发送系统按键、不改用户配置或音频设备。构建只生成当前 worktree 下的 App，不会安装或启动它。

## 人工验收步骤（本开发包尚未执行）

测试前正常退出旧 App，备份 `local.ben.RemoteVibe` 偏好，然后打开本 worktree 的 `mac-app/build/Remote Vibe.app`。两份 App 的 bundle id 相同；旧版仍运行时，打开新版只会唤起旧版。`status.json` 中的 `appVersion` 应为 `0.4.1`。

1. Google 选择一颗普通键，单击设明确动作，长按设“遥控器语音（长按后开麦）”，保存。在目标输入框中长按该键说话、松开；确认正常出字且没有额外短按动作。
2. 把同一颗键设为单击“遥控器语音（按住说话）”，其他两项未设置。确认按下即请求开麦、松开后出字。
3. 快速点按后立即松开，等待两秒；确认不出现迟到的语音输入，下一次正常长按仍可用。
4. 一段语音正在收尾时再按普通键；确认不会中断前一段。使用菜单“立即结束本次语音”，确认 Fn 释放、默认输入恢复。
5. 按住语音映射键时保存配置、断开遥控器或让 Mac 睡眠；确认取消后不会继续收音或留下 Fn。恢复连接后重新按下可用。
6. Google 原语音键按住说话仍正常。切换到小米 RC003，确认原语音键输入及原配置保留，动作菜单不提供普通键开麦。
7. 无语音时关闭设置页，确认不扫描蓝牙；语音结束后系统默认输入恢复，默认输出不改变。

恢复旧版前退出开发包并恢复偏好备份；旧版不认识新增 `remoteVoice` 动作。不要让旧版读取新增动作配置后直接保存，以免丢失配置。
